# Roulette Wheel Audio Options Research

## Executive Summary

**Recommended Approach**: Use a **hybrid approach** combining procedurally generated sounds for the continuous rolling/rumbling (filtered noise synthesis) with the existing procedural bounce/tick sounds, enhanced with dynamic volume control synced to ball velocity. The current procedural implementation provides a solid foundation; enhancements should focus on adding a continuous rolling sound and improving realism through velocity-based modulation. This approach keeps the binary small, requires no external assets or licensing concerns, and integrates cleanly with the existing architecture.

## 1. Option Analysis

### 1.1 Procedural Audio Generation (Current Approach + Enhancements)

**Current Implementation**: The game already uses procedural synthesis for tick, bounce, settle, and chime sounds in `/Users/chris/devel/home/roulette-wheel/audio/audio.go`. These are generated using:
- Sine wave combinations with exponential decay envelopes
- Simple LCG-based noise for texture
- Pre-generated byte buffers played on demand

**Pros**:
- Zero file size overhead (sounds generated at runtime)
- Perfect synchronization with game physics (can modulate in real-time)
- No licensing concerns
- Already partially implemented
- Infinite variation possible

**Cons**:
- Harder to achieve highly realistic sounds without complex DSP
- Requires audio programming expertise for quality results
- Rolling/rumbling sounds are more challenging than impact sounds

**Feasibility for Rolling Sounds**:

A realistic rolling sound can be synthesized using **filtered noise**:
- Start with white noise (random samples)
- Apply a low-pass filter to create brown/pink noise (rumbling character)
- Modulate filter cutoff frequency and volume based on ball speed
- Add subtle amplitude modulation for irregularity

**Techniques**:
1. **Brown Noise** (1/f^2): Deeper, softer rumble - ideal for wooden track
2. **Filtered White Noise**: Controllable via low-pass filter cutoff
3. **Granular Synthesis**: More complex but allows speed-to-pitch mapping

**Complexity**: Medium. Can be implemented with ~50-100 lines of additional code.

### 1.2 Embedded Audio Samples

**Approach**: Embed pre-recorded WAV/OGG files using Go's `//go:embed` directive (available since Go 1.16).

**Ebitengine Format Support**:
- **WAV**: Supported via `github.com/hajimehoshi/ebiten/v2/audio/wav`
- **OGG/Vorbis**: Supported via `github.com/hajimehoshi/ebiten/v2/audio/vorbis`
- **MP3**: Supported via `github.com/hajimehoshi/ebiten/v2/audio/mp3`

**Looping**:
- `audio.NewInfiniteLoop(src, length)` creates seamlessly looping audio
- For smooth loops, add ~0.1s of data after loop end for blending

**File Size Implications**:
| Format | Quality | ~10s Rolling Sound |
|--------|---------|-------------------|
| WAV (16-bit, 44.1kHz, stereo) | Lossless | ~1.7 MB |
| OGG (128kbps) | Good | ~160 KB |
| MP3 (128kbps) | Good | ~160 KB |

A complete sound set (rolling loop + bounces + settle) would add approximately:
- WAV: 2-3 MB to binary
- OGG/MP3: 200-400 KB to binary

**Pros**:
- Potentially more realistic with high-quality recordings
- Easier to achieve specific sonic character
- Well-understood workflow

**Cons**:
- Increases binary size
- Licensing concerns for sound sources
- Less dynamic (can't vary pitch/timbre based on exact speed without resampling)
- Loop points require careful editing

### 1.3 Hybrid Approach (Recommended)

**Strategy**: Use procedural audio for most sounds, selectively use samples only where procedural falls short.

| Sound Type | Recommended Approach | Rationale |
|------------|---------------------|-----------|
| Rolling/Rumbling | **Procedural** (filtered noise) | Easy to modulate with speed; continuous sound |
| Tick (slot crossing) | **Procedural** (current) | Already good; sharp transients work well |
| Bounce | **Procedural** (current + enhancement) | Add metallic ring harmonics |
| Settle | **Procedural** (current) | Works well |
| Chime | **Procedural** (current) | Musical tones are ideal for synthesis |

**Why Procedural for Rolling**:
- Real-time control of intensity based on `ball.AngularSpeed`
- No loop artifacts (generated continuously)
- Speed variations sound natural, not pitch-shifted

**When Samples Would Help**:
- If extremely realistic "wooden ball track" character is required
- For ambient casino sounds (crowd, other tables) - not needed for this game

### 4.2 Proposed Enhancements

#### A. Add Continuous Rolling Sound

```go
// New fields in Audio struct
type Audio struct {
    // ... existing fields ...
    rollingPlayer *audio.Player
    rollingSound  []byte
    isRolling     bool
}

// Generate a loopable rolling sound (filtered noise)
func generateRollingLoop() []byte {
    duration := 0.5 // 500ms loop
    samples := int(SampleRate * duration)
    buf := make([]byte, samples*4)

    // State for filtered noise
    var prevSample float64 = 0
    filterCoeff := 0.95 // Low-pass coefficient (higher = darker sound)

    for i := 0; i < samples; i++ {
        // Generate white noise
        noise := randomNoise()

        // Simple 1-pole low-pass filter -> brown-ish noise
        filtered := filterCoeff*prevSample + (1-filterCoeff)*noise
        prevSample = filtered

        // Apply gentle envelope for loop smoothness
        t := float64(i) / float64(samples)
        envelope := 1.0
        if t < 0.05 {
            envelope = t / 0.05 // Fade in
        } else if t > 0.95 {
            envelope = (1 - t) / 0.05 // Fade out
        }

        sample := filtered * envelope * 0.3
        val := int16(sample * 32767)

        binary.LittleEndian.PutUint16(buf[i*4:], uint16(val))
        binary.LittleEndian.PutUint16(buf[i*4+2:], uint16(val))
    }
    return buf
}

// Start rolling sound when ball begins orbiting
func (a *Audio) StartRolling() {
    if a.muted || a.rollingSound == nil {
        return
    }
    loop := audio.NewInfiniteLoop(bytes.NewReader(a.rollingSound), int64(len(a.rollingSound)))
    player, err := a.context.NewPlayer(loop)
    if err != nil {
        return
    }
    a.rollingPlayer = player
    a.rollingPlayer.SetVolume(0.3)
    a.rollingPlayer.Play()
    a.isRolling = true
}

// Update volume based on ball speed
func (a *Audio) UpdateRollingVolume(speedRatio float64) {
    if a.rollingPlayer == nil || !a.isRolling {
        return
    }
    volume := math.Max(0.05, math.Min(speedRatio, 1.0)) * 0.4
    a.rollingPlayer.SetVolume(volume)
}

// Stop rolling when ball settles
func (a *Audio) StopRolling() {
    if a.rollingPlayer != nil {
        a.rollingPlayer.Close()
        a.rollingPlayer = nil
    }
    a.isRolling = false
}
```

#### B. Integration with Ball Physics

In `main.go`, add continuous audio updates:

```go
func (g *Game) Update() error {
    // ... existing code ...

    // Update rolling sound based on ball state
    if g.ball.Phase == ball.PhaseOrbiting || g.ball.Phase == ball.PhaseDropping {
        if !g.audio.IsRolling() {
            g.audio.StartRolling()
        }
        // Calculate speed ratio for volume
        speedRatio := math.Abs(g.ball.AngularSpeed) / ball.InitialAngularSpeed
        g.audio.UpdateRollingVolume(speedRatio)
    } else if g.ball.Phase == ball.PhaseSettled || g.ball.Phase == ball.PhaseIdle {
        g.audio.StopRolling()
    }

    return nil
}
```

#### C. Enhance Bounce Sound

Add metallic harmonics for more realistic ball-on-metal slot bounce:

```go
func generateBounce() []byte {
    duration := 0.15 // Slightly longer
    samples := int(SampleRate * duration)
    buf := make([]byte, samples*4)

    for i := 0; i < samples; i++ {
        t := float64(i) / SampleRate

        // Fast impact decay
        impactEnv := math.Exp(-t * 50)
        // Slower metallic ring
        ringEnv := math.Exp(-t * 20)

        // Impact component (thud)
        impact := math.Sin(2*math.Pi*180*t)*0.4 +
                  math.Sin(2*math.Pi*360*t)*0.2

        // Metallic ring component (higher frequencies)
        ring := math.Sin(2*math.Pi*2400*t)*0.15 +
                math.Sin(2*math.Pi*3600*t)*0.08 +
                math.Sin(2*math.Pi*4800*t)*0.04

        // Noise for texture
        noise := randomNoise() * 0.02 * impactEnv

        sample := impact*impactEnv + ring*ringEnv + noise
        sample *= 0.5

        val := int16(sample * 32767)
        binary.LittleEndian.PutUint16(buf[i*4:], uint16(val))
        binary.LittleEndian.PutUint16(buf[i*4+2:], uint16(val))
    }
    return buf
}
```

### Enhanced Synchronization for Rolling Sound

```go
// In main.go Update():
func (g *Game) Update() error {
    // ... input handling ...

    // Update ball physics
    g.ball.Update(g.wheel.Rotation, g.wheel.AngularSpeed)

    // Sync rolling sound with ball state
    switch g.ball.Phase {
    case ball.PhaseOrbiting, ball.PhaseDropping:
        g.syncRollingAudio()
    case ball.PhaseBouncing:
        g.audio.StopRolling() // Or fade out quickly
    case ball.PhaseSettled, ball.PhaseIdle:
        g.audio.StopRolling()
    }

    return nil
}

func (g *Game) syncRollingAudio() {
    if !g.audio.IsRolling() {
        g.audio.StartRolling()
    }

    // Volume based on absolute angular speed
    maxSpeed := ball.InitialAngularSpeed
    currentSpeed := math.Abs(g.ball.AngularSpeed)
    volumeRatio := currentSpeed / maxSpeed

    g.audio.UpdateRollingVolume(volumeRatio)
}
```
